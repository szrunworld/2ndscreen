# new_application_marker：新投递 / 新招呼的呈现

**结论**：这个客户端里没有单独叫『投递』的标记或分组。候选人主动发起的会话归在顶部页签『新招呼(N)』下，另有筛选『更多→牛人发起』。在『全部』页签里，行上没有任何区分新招呼和普通会话的标记，只有未读角标。

## 步骤与点击

| # | 来源 | 内容 |
| --- | --- | --- |
| 0 | 点页签『新招呼(504)』 | 10 个可见行都带未读角标 |
| 1 | 点子筛选『未读』 | 录制期间新到一条招呼：页签计数变为 505，新行排在第一行 |
| 2 | 『更多』→『牛人发起』 | 可见行与新招呼相同 |
| 3 | 录制开始时协调者已经打开的会话（候选人A） | 只有候选人一条消息和一张职位卡片『10月4日 沟通的职位-…』，招聘方没有回复；换电话、换微信、约面试、附件简历都是灰的 |
| 4 | 『沟通中』里已读会话（候选人M）的详情 | 聊天区开头有系统提示『牛人候选人M向您发起了沟通』 |
| 5 | 同类会话（候选人N）的在线简历弹层侧栏 | 『沟通中，14:33 向您发起沟通，沟通职位 视觉算法工程师』 |

**没有打开任何未读的新招呼会话**。打开会话会把它标为已读，候选人可能看到已读回执，这是对外可见的副作用。协调者已确认只读阶段不做。

## 标注说明

- 只把『新招呼』页签里的行标为 `is_new_application: true`。『新招呼』就是『新投递』，这一点是根据产品语义推断的，需要 N 阶段由用户确认。
- 『全部』页签和『牛人发起』筛选下的行放在 `x_conversations_unclassified`。只看这一步的快照，无法判断这些行是不是新投递。
- 步骤 3 的会话不在可见列表中，所以没有断言它属于新招呼。

## 未观察到

- 新招呼会话第一次被打开时的详情（不打开，避免已读回执）。
- 打开会话后『新招呼(N)』计数会不会减少。
- 名称或含义为『投递』的任何文案。
