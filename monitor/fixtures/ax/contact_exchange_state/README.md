# contact_exchange_state：联系方式交换状态

| # | 状态 | 界面呈现 |
| --- | --- | --- |
| 0 | 未请求（候选人P） | 『换电话』『换微信』都可用，外层各有可按 AXGroup；聊天区没有交换相关的系统提示 |
| 1 | 微信待同意（候选人M） | 聊天区居中系统提示『请求交换微信已发送』；『换微信』置灰（只剩裸 StaticText），『换电话』仍可用 |
| 2 | 不可用（候选人A，招聘方未回复） | 『换电话』『换微信』都置灰，界面没有说明原因 |
| 3 | 已交换电话 | 『更多→已交换电话』筛选结果为『暂无牛人』，**未观察到**已交换的会话 |
| 4 | 已交换微信 | 『更多→已交换微信』筛选结果为『暂无牛人』，**未观察到** |

## 观察结论

- **待同意的判断**：系统提示文案『请求交换微信已发送』，加上对应按钮置灰。
- **电话请求的提示**：按客户端的命名习惯，电话请求后可能出现『请求交换电话已发送』，但这次没有观察到，不能写进规则。
- **未观察到**：已同意（联系方式可见）和已拒绝的文案。
- **筛选可以作为补充信号**：『已交换电话』『已交换微信』这两个列表筛选是独立的。
- **不能用『已交换』筛选来确认结果**：录制时两个筛选都是空的，H3 和 E 要等 N 阶段有真实交换后再补夹具。

本场景没有点击任何交换按钮。
