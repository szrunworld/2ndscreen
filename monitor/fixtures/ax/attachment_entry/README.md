# attachment_entry：附件简历入口

## 步骤与点击

| # | 操作 | 结果 |
| --- | --- | --- |
| 0 | 打开候选人P 的会话（没有附件） | 『附件简历』是 AXGroup，视觉上置灰 |
| 1 | 点『附件简历』 | 按钮下方弹出确认气泡『确定向牛人索取简历吗？』，带 AXButton『取消』和『确认』 |
| 2 | 立刻点『取消』 | 气泡消失。元素文本序列与第 0 步逐项相同，没有发出请求 |
| 3 | 打开候选人N 的会话（候选人已发附件） | 『附件简历』变成 **AXLink**；聊天区出现 PDF 卡片：AXHeading『<文件名>.pdf | 3』、按钮『点击预览附件简历』，卡片右上有一个 20×20 的无标签下载图标 |
| 4 | 点『附件简历』（Link） | 窗口内出现 AXWebArea『PDF预览』，带 AXButton『切图』，顶部有 3 个无标签图标（截图上看是放大、复制/打印类、下载），右上有关闭按钮 |
| 5 | 点预览右上的关闭 | 回到会话详情 |

## 观察结论

- **附件是否可用**：可以直接从 AX 判断。看两点：『附件简历』的角色（AXGroup 表示没有附件，AXLink 表示有附件），以及聊天区有没有『点击预览附件简历』。这可以作为 `attachment_available` 的判断依据。会话列表里的预览也会显示 PDF 文件名。
- **没有附件时**，点『附件简历』等于『求简历』，会弹出『确定向牛人索取简历吗？』。动作代码只能在白名单允许的情况下点『确认』，本次没有点。
- **PDF 预览的文字层在 AX 中逐行可读**，内容包括候选人电话、邮箱、链接，本次录到 256 个 StaticText。夹具里把这些整体删掉了。产品不读简历正文，Monitor 应避免读取这一层。如果读到了，也不能写进 evidence。
- 预览打开期间，`state` 不带 `--window-id` 会报 `no window on screen`；带上 `--window-id` 就正常。Driver 应始终带上 window id。
- 预览里和附件卡片上**没有『转发』或『发邮件』入口**，只有下载图标（没有点，下载不在允许范围内）。
