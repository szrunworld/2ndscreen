# BOSS macOS P0 能力矩阵

本次实测支持以“已有会话中的在线简历页面采集”作为 P1 首条路线。原始附件下载仍未验证：当前账号的“已获取简历”过滤列表为空，不能用模拟附件声称生产路径可用。推荐来源、验证码与真实附件保存对话框也没有完成实测。

## 实测结果

| 能力 | 结果与证据 | 对实现的要求 |
| --- | --- | --- |
| 创建专用屏幕 | 1440×900 HiDPI 成功，初次及两次 side instance 重启后均可重建 | 屏幕有独立 Socket 和可回收超时 |
| 启动并绑定 BOSS | 加载窗口 340×500，随后替换为主窗口；两个 windowID 不同 | 等主窗口稳定，不缓存加载窗口 ID |
| 尺寸与坐标 | 初期主窗口 1280×768，调整后出现 1360×848；重绑定后 1440×875。屏幕重排还改变全局 x | 使用实际 frame 和截图 covers；1440×900 是屏幕配置，不是所有窗口的固定尺寸 |
| 截图 | 1360×848 pt 窗口得到 2720×1696 px PNG；后续尺寸变化仍可截图 | 比例从实际图片和覆盖范围计算，不能硬编码 2x |
| 读取会话列表 | AX 可读取候选人行、岗位、消息和时间 | 先按布局与身份构建引用，操作前重新观察 |
| 打开会话 | 元素点击 event.click 后候选人标题与在线简历入口出现 | 点击返回 ok 早于页面更新，必须等待后置条件 |
| 打开在线简历 | 初次、重复打开、两次重启重绑定后均成功 | 用在线简历链接，再等待简历图像区域；“正在加载简历”不是成功 |
| 读取简历正文 | AX 只暴露 AXWebArea + AXImage，正文没有可用文字树 | 图片区域用本地 OCR；保留原图，不能从会话摘要伪造全文 |
| 本地中文 OCR | Apple Vision accurate 模式，zh-Hans/en-US 可识别正文与按钮 | 无远端模型调用；OCR 结果包含置信度和像素框 |
| 展开折叠内容 | OCR 找到“查看全部”，转换坐标后后台点击；下一图 OCR 为“收起” | 全文采集前处理折叠区域；无法验证展开则标部分采集 |
| 简历后台滚动 | event.wheel 连续改变正文，截图已保存至底部；两次重启后再次滚动也改变内容 | 每步观察实际进度；amount 合法范围为 1–50 |
| 底部判断 | 内容经过多次滚动后，最后两次局部图片哈希相同；截图同时见底部说明、滚动条到末端 | 相同图片只触发检查，必须结合独立末尾证据 |
| 长页采集 | 展开正文后保存 18 张顺序截图（含底部重复确认帧），文件可读且有哈希 | P0 证明分屏采集；自动拼接、重叠验证和最终归档仍由 A4/A8/A2 实现 |
| 关闭简历 | 根据当前弹层关闭控件位置点击，在线简历覆盖层消失 | 关闭弹层与关闭应用窗口必须区分 |
| 无附件分支 | 点击附件简历后出现“请求简历并回复内容”的确认框；点击取消并验证提示消失 | unavailable/request_dialog，不得点击确认或发送消息 |
| 原始附件下载 | 未验证；“已获取简历”列表显示暂无牛人 | original-only 报未满足能力/无可用附件，不能用截图顶替 |
| 焦点与鼠标 | 三次连续滚动采样的前后前台应用及指针完全相同；一次打开会话同样如此。另一次采样期间用户活动造成位置与前台变化 | 只能报告已观察样本；尚未证明所有输入、全部用户并发场景永不抢焦点 |
| 重启恢复 | 专用 side instance 重启两次，屏幕重建，BOSS 原进程重绑定后仍能打开/滚动/关闭简历 | 窗口和显示器几何重新读取；不重启用户 BOSS 账号 |

## 给开发 agent 的操作约束

1. 状态读取与事件发送之间存在异步加载。等待条件以页面标志为准，不能把固定 sleep 后的第一帧直接当成终态。
2. 输入能力按页面和路由区分。当前在线简历中的坐标点击可以展开文字，旧 BOSS 助手对某些列表坐标点击失败的注释仍应保留，不做全局结论。
3. 真实截图包含用户和候选人信息，仅留本地；开发测试使用合成文本和布局，不把原图纳入仓库 fixtures。
4. 本轮并未调用模型理解每一步。P0 中用于读图的协调者判断是能力调查，不属于已经实现的自动学习系统；零模型的运行时验收必须由 A3/A6/A7 的真实计量证明。
5. 本地 Vision 只做识别、比较、裁剪拼接，桌面动作只经过 Session。A4 决定什么页面、什么人、什么结果；A8 不做业务决策。

## P0 出口

在线页面采集路线可以进入 P1 开发：后台导航、图片正文识别、展开、滚动和重绑定已有真实证据。原始附件路线保留未验收状态；现阶段不能承诺 original-only 成功。列表多页遍历、长图自动拼接完整性、重启任务账本恢复和批量身份关联仍是后续实现与验收任务，不用 P0 的手工验证替代。

## 集成复核：本地拼接（2026-10-04）

协调者用 A8 最终原生 helper 复核本地保留的 17 张简历区域截图（1468×1696 px）。逐像素对齐发现，正常滚动时正文内区完全一致，变化集中在右侧 8 px 滚动条及下一帧顶部 2 px 的视口裁切边缘。直接拼接整个视口会被严格的内容一致性检查判为 gap。

使用内容 ROI x=0、y=2、width=1452、height=1694 后，13 次 800 px 滚动、末次 388 px 滚动均正确拼接，末尾两张重复帧被去重，结果 1452×12482 px、hasGap=false。此 ROI 对应本次 2x 样本的顶部 1 pt 与右侧 8 pt 留边；产品实现必须由实际 covers 和像素尺寸换算，不能硬编码 2x。原始截图保留为本地诊断证据，不进入仓库。

本次保留区域图不含原始第一页，因此只证明连续页面拼接，不证明已完成整份简历采集。完整性仍需 A4 对顶部、展开、底部独立证据及 A2 归档的最终验收；正文内部发生变化时，严格 gap 检测继续有效。

## 后续真实联调阻断（2026-10-04 11:19–11:25）

已合并 A1/A2/A4/A5/A8 后，协调者尝试真实模块串联，尚未进入候选人操作即停在虚拟屏幕创建：适配器的 `screen create` 在 15 秒超时，单独延长等待至 60 秒仍未返回。重启本轮专用 side instance 后，以 `--no-hidpi` 创建同尺寸屏幕也在 35 秒截止前未返回。进程采样显示主线程停留在 VirtualDisplay.selectSystemMode / CGCompleteDisplayConfiguration 的 WindowServer 调用。`screen list` 曾正常返回空列表，故不是简单的 Socket 不存在。

已停止本轮启动的两个专用实例，未关闭 BOSS 或重启系统显示服务。此次尝试没有执行候选人点击、简历请求或消息发送。该问题可能涉及当前系统显示配置，尚未证明是 Runtime 实现缺陷；真实端到端验收继续标为未通过，不能用此前 P0 成功或合成测试替代。定位证据仅保留本机 P0 目录。

## 恢复后的集成复核（2026-10-04 11:30–11:59）

等待此前虚拟显示器完全释放后，再次启动专用实例，1440×900 HiDPI 创建在约 1.4 秒内成功。BOSS 原进程重新绑定，窗口实际尺寸为 1440×875。此前屏幕创建阻断已恢复，但仍不能据此认定整个任务验收通过。

- 补入真实首帧后，18 张保留截图经原生 helper 拼接得到 1452×13282 px、hasGap=false；这仍是离线图像验证。
- 实际简历顶部没有 BOSS 标志，只有头像、姓名、活跃状态及摘要。原先依赖平台标志的顶部判断已退回修复，改为参数化姓名位置及受控滚动起点验证，合成回归 39 项通过。
- 真实会话打开时，消息输入框先于姓名和岗位完成加载。修复后主协调者复测 open_candidate 的执行与校验均通过，身份置信度为 strong。
- 随后 open_resume 仍被身份验证拒绝。实际弹层右侧只有操作和沟通状态等内容，没有预期的独立姓名文字；姓名在左侧简历图像中。背景会话的 AX 姓名仍可被枚举，不能把几何上位于弹层内的背景文字当作弹层身份。已安排局部 OCR 身份校验修复，尚未验收。
- 岗位筛选点击文字、箭头和父容器中心均返回输入成功，但后续 AX 与截图未显示选项。一次 8 秒、约 10 ms 间隔的目标进程窗口列表采样未发现新增窗口；这不能排除 WebView 内的瞬时弹层。筛选路线仍未验证成功，不能绕过它宣称指定岗位采集通过。

真实联调只做导航、读取与采集验证，没有发送招聘消息、请求简历或打招呼。原始候选人证据保留本机私有目录；工作 agent 只收到脱敏布局与行为描述。

## 岗位筛选路由补充（2026-10-04 12:01–12:08）

协调者用临时原生 AX 探针验证：对当前筛选框右侧箭头 `AXGroup`（窗口相对位置 416,31，尺寸 12×12，声明 `AXPress`）直接执行 `AXPress`，岗位下拉会出现。连续三次打开成功，其中一次在窗口重新绑定之后；每次探针前后的前台 PID 和真实指针位置均相同。首次打开后，从新增 AX 文本中唯一匹配目标岗位，再用已有原生 `event.click` 选择，等待后的筛选标签与选项完整文字精确一致。

父容器的 `AXPress` 虽返回成功但无页面变化；`AXShowMenu` 打开的是浏览器上下文菜单，已用 Escape 关闭，不是岗位选择路由。下拉打开后，背景候选人行仍出现在 AX 树中，必须排除打开前已有的元素，不能按坐标区域和岗位文本直接取第一个匹配。

这证明了必要原语的可行性，尚未等同于产品接口通过。现有 InputEngine 对 Web 内容统一走事件点击，会跳过此 AX 路由；已计划增加显式、可失败的辅助功能按压选项，并保留默认点击行为。接入后仍需经 Session 和 workflow 再次实测。
