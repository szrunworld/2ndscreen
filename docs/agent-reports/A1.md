## 实现要点

**Adapter（second-screen.ts）**
- 每条 2ndscreen 命令都带 `SECONDSCREEN_SOCKET=<options.socket>`，经注入的 `CommandRunner` 执行，单条上限 `commandTimeoutMs`（默认 15 s），全部接受 AbortSignal。
- `ensureScreen`：side instance 不应答时用 `open -g -n --env SECONDSCREEN_SOCKET=… <app>` 启动，有界轮询 20×500 ms；无 app 报 `capability_missing`。屏幕名为 `profile.id`，尺寸为 profile 逻辑尺寸，创建时带 `--owner-pid <worker pid> --idle-timeout 30m`；已有屏幕尺寸不同时 `screen resize`，失败报 `conflict`。从不销毁屏幕。
- `bindApp`：沿用 setup.ts 的 planBoss 语义。未运行则 `app launch --fill`（`launchedByRuntime: true`）；已在本屏幕则直接附着；在别处运行时，没有 `takeOver` 就报 `conflict`，details 带 pid、进程启动时间和 bundle，有 `takeOver` 才 `window move --fill`。随后等待主窗口：宽度至少为屏幕一半，且连续两次读取 windowID 与 frame 相同（P0：340×500 加载窗口会换 windowID），上限 30 s。进程身份由 `lsappinfo` 的 bundle 和 `ps -o lstart=` 的启动时间组成，两者在绑定时重新读取，不凭 pid。
- `observe`：`state --window-id` 固定到绑定窗口。windowID 或 pid 不符报 `window_lost`。frame 每次重读，几何变化会跟随。截图的像素尺寸取自 PNG 头，`covers` 为实测窗口 frame，并计算 sha256；`region` 用 `sips` 按图片实际比例裁剪，`covers` 按取整后的像素回算。
- `act`：只接受元素 index 与 relative 点（其余定位器由 Session 解析，送来时返回 failed/invalid_input）。relative 点按 contentFrame 换算，落在窗口外则失败。CLI 的 “no element N” 映射为 `stale_snapshot`；命令超时或被取消时结果为 `unknown`，因为事件可能已送达，调用方不得重发。
- 错误分类：`classifyCliError` 把 CLI 文本映射为 capability_missing、permission_missing、window_lost、snapshot_stale、not_found、invalid_input、conflict、io。
- `capabilities`：权限在已有 agent 屏幕上探测，方式是对 pid 0 执行 `window release`，以及把截图写入临时文件后删除；没有屏幕时报 false，含义是未验证。按 P0 能力矩阵，backgroundClick 和 backgroundScroll 为 true，backgroundType 为 false（P0 未验证）。
- `createCommandRunner`：基于 execFile。非零退出照常 resolve 并带退出码；超时报 `timeout`，外部 abort 报 `cancelled`，程序不存在报 `capability_missing`。

**Session（session.ts）**
- 租约：scope 为 `leaseScopeKey(bundleId, account?.accountKey)`，holder 为 runtime，ownerPid 默认取 process.pid。拿到租约后立即开始每 ttl/3 续期一次，在 ensureScreen/bindApp 之前，所以准备阶段超过 ttl 也不会失效。续期失败或本地判定过期就 fence：中止该租约的 AbortSignal，进行中的原生命令、Bridge grant 和 open 的准备步骤都会被打断，之后的操作一律抛 `lease_held`。被 fence 的会话关闭时不 release 窗口。
- open 部分失败时只清理自己拥有的资源：释放租约，只有本次 launch 的窗口才 releaseWindow；附着的窗口和 bundle 不符的窗口都不动。
- 串行：observe、act（包括语义解析时的重新读取）和 rebind 共用一个操作槽，第二个直接报 `actor_busy`，不排队，避免读取插进另一个动作的解析和投递之间。grant 期间所有原生操作都报 `actor_busy`。
- 快照：元素 index 只对本会话最近一次读取有效。任何 act、rebind 或 grant 都会让它失效，失效时返回 `stale_snapshot`，不调用 adapter。role/label/labelPattern/within 在新读取上解析，必须恰好匹配一个，0 个报 not_found，多个报 conflict。ocr/template 定位器经 LocalVision 解析：截图像素按 `covers` 换成全局坐标，再换成 relative；未注入 vision 或 vision 没有 findTemplate 时报 `capability_missing`。
- external-submit 在 `submitAllowed=false` 时抛 `forbidden_effect`；其余请求经 `validateActionRequest` 校验。
- `check` 支持 element、text、page、window、file（minBytes/stableMs）和 all/any。evidence 不包含页面文字或 pattern。`waitFor` 用 `validateWaitSpec` 校验上限，每次读取都受截止时间约束；截止时返回 ok:false，外部取消抛 `cancelled`；只有 file 条件时不读窗口。
- `rebind`：先 ensureScreen 再 bindApp(takeOver=任务参数)。遇到 conflict 时，只有 pid 和启动时间都与本会话 launch 的进程一致（例如屏幕重建）才用 takeOver 重绑；同 pid 但启动时间不同视为他人进程，不动。`launchedByRuntime` 随同一进程保留。
- `close`：中止进行中的操作和 grant，等它们确认结束后，再按 keepWindow 决定是否释放窗口，最后释放租约。重复调用无副作用。

结果：71/71 通过（其中 A0 契约测试 31 条、second-screen 15 条、session 25 条），连续 5 次运行均通过；typecheck 无错误。

测试全部使用 fake CommandRunner、fake DesktopAdapter、内存 LeaseStore、临时目录和合成 PNG。唯一的真实子进程是 createCommandRunner 自测里的 `/bin/sh` 和 `/bin/sleep`。没有启动 2ndscreen、屏幕或 BOSS，也没有调用模型。

覆盖的失败路径：side instance 未运行或无 app、屏幕尺寸冲突、加载窗口替换、未授权接管、bundle 不符、窗口替换导致 window_lost、几何变化、stale index、权限缺失、命令超时得到 unknown、预先取消、租约冲突（同 bundle 不同账号）、open 失败时归还租约、续期失败的 fence（中止 grant 和进行中的动作）、租约过期、close 等待进行中的动作再释放窗口和租约、并发 act/observe/rebind/grant 被拒、慢启动期间持续续期、open 期间失租、部分失败只清理自己拥有的资源、waitFor 的超时、取消和非法上限。

## 协调者确认的契约缺口处理

1. 打开后没有绑定账号的方法：租约保留 open 时的 scope（`bundle:*` 或 `bundle:acct`），每 ttl/3 续期；账号核对由 runner/workflow 负责。同一 bundle 的 scope 互相重叠，`*` 仍然独占。
2. 屏幕名使用 `profile.id`。旧助手放在 `boss` 屏幕上的 BOSS 窗口需要显式 takeOver 才会被接管。
3. CLI 不报告内容区，`contentFrame` 以实测的窗口 frame 代替。这是已记录的退路，不是经过证明的纯内容区；截图仍使用实测的 `covers`。

## 未验证项与已知限制

- 未在真实 2ndscreen/BOSS 上运行（按规则由协调者实测）。CLI 输出格式依据 `Sources/ScreenCLI/DriverCommands.swift`、`main.swift` 和 `ControlProtocol.swift` 阅读得出。
- `contentFrame` 包含标题栏，relative 坐标基于整个窗口；若需要纯内容区，需在 2ndscreen 的 state 输出里新增字段（属 A7 范围）。
- WindowProfile 的 `appVersion` 和 `locale` 未填写：CLI 不提供，DesktopAdapter 也没有对应返回字段。
- `focusChanged` 未填写：CLI 不报告前台应用和指针变化。P0 只有采样证据。
- rebind 时，“首次 bindApp 返回 conflict”与“带 takeOver 重试”之间存在很小的竞态窗口：若期间换成了另一个进程，adapter 可能已经移动了该窗口，Session 事后会报 conflict。adapter 的接口没有“只移动指定启动时间的进程”这一参数。
- `backgroundType` 按 P0 报 false。capabilities 在没有 agent 屏幕时把两项权限报为 false，含义是未验证。
- 屏幕的 30 分钟空闲超时：等待用户登录等长时间空闲后屏幕可能已被回收，需要 rebind，此时会重新创建屏幕。
- 续期计时器调用了 `unref`，不会单独让进程保持存活；长期 worker 本身负责保持事件循环。
- 关闭时不退出本次 launch 的应用（接口没有 quit）；`keepWindow=false` 只做 `window release`。

## 接入说明

- A6/A7：`createSecondScreenAdapter({ cli, socket, app, run: createCommandRunner(), screenshotDir })` → `createSessionManager({ adapter, leases: taskStore, policy, vision })`。截图目录由调用方清理。
- A5：Bridge 在 `session.withExclusiveActor('bridge', grant => explore(..., grant.signal))` 内运行。`grant.signal` 在调用方取消、失租或会话关闭时都会触发。explore 必须在子进程退出后才 resolve。
- A4/A3：动作前先 `observe`，再用同一 `snapshotId` 的 index；需要跨步骤复用的定位器请用 role/label 或 ocr/relative。
