## 实现要点

### Swift：只包装，不另造 Agent

- `ExplorationBridge` 用现有 `TarsAgent`（Model/ActionParser/Planner/Agent 原样复用），只把它的 `AgentScreen` 和 `VisionModel` 包一层：
  - `RecordingScreen.perform`：唯一通往 App 的路径。先判定效果类，越权直接拒绝不发送；发送前写 `action_started`，返回后写 `action_finished`（含实际结果）。不重试，所以每个动作至多执行一次。抛错时结果记为 `unknown`（可能已送达）。
  - `screenshot` 成功后写 `observed`（快照 ID `<unitAttemptId>-sN`，窗口几何实时读取，contentFrame 与 A1 一致取窗口 frame）。
  - `elements` 记住 Agent 实际读到的元素；动作的 locator 来自 Agent 实际解析出的元素（role + label，`resolvedElement` 带 frame），没有 label 时用窗口内比例坐标。**学习步骤只来自实际发送的 InputAction 与 AX 元素，不来自模型文字。**
  - `BudgetedModel`：每次请求前检查取消/截止/轮数/token；请求后写 `model_usage`。
- 效果分类：scroll→read；click/type/key→navigation；Enter（return/enter/kpenter）与含换行的 type→external-submit，一律拒绝；drag 无契约形态且需真实指针，拒绝。不在 `allowedEffects` 内→`forbidden_effect`。Planner 自身的“发送前停住”（held）也映射为 `forbidden_effect`，不算完成。
- 点击点落在绑定窗口外：不发送（会落到别的窗口）。
- 终止事件与错误分离：模型 finished→`unit_finished`（steps=实际 action_finished 数，可选提案）；轮数用于模型且耗尽→`budget_exhausted`；轮数因截图失败流失→`error`（附屏幕错误）；模型报错/call_user→`error`；超时→`timeout`；无模型→`model_unavailable`（立即，退出码 1）；请求无效或 `SECONDSCREEN_SOCKET` 与请求不符→`unit_failed/error`，退出码 2。
- 提案：仅当所有已执行步骤状态都是 ok 时给出；type 值或元素 label 恰等于某参数值时还原为 `{{slot}}`；postconditions 取请求的 `expectedPostconditions`。提案只是建议，V2 仍由 Runtime 验证后写入。
- 取消：SIGTERM/SIGINT 经 DispatchSource 调 `cancel()`。无动作进行中→立即写 `unit_failed/cancelled` 并退出（若模型请求未返回，先补一条 tokens unknown 的 `model_usage`，避免漏计）；动作进行中→等该动作的 `action_finished` 后不再执行新动作，写 cancelled 结束。写入有锁，终止行之后不会再有任何行。
- 用量：`purpose/reason` 取 `usageContext`，缺省 `ui/missing_procedure`。`ChatCompletionsModel` 不报 token，一律 `"unknown"`；配置 `maxTokens` 时按 checkBudget 规则，首次调用后即 `budget_exhausted`。模型若实现 `TokenReportingModel` 则累计真实数值。
- 旧 ProcedureStore 不使用（`procedures = nil`），不会写旧流程库。

### Node：agent-bridge.ts

- `explore` 先 `validateExplorationRequest`，再核对 grant：holder 必须为 `bridge`，socket/screenId/pid/windowId 与请求一致，否则 `invalid_input`，不启动进程。已 abort 则不启动，返回 cancelled。
- 启动 `<cli> agent-bridge`，env 合并 `options.env` 与 `SECONDSCREEN_SOCKET=request.session.socket`；写一行请求后关闭 stdin。
- 每行用 `parseBridgeEvent(line, {taskId, unitAttemptId})`；另加顺序规则：`action_finished` 必须有对应 `action_started`，stepId 不可重复，终止行之后不能再有行，`unit_finished.steps` 必须等于已完成步骤数，`unit_finished` 必须配退出码 0。任何违反→`error` 并 SIGTERM，继续读完输出以免子进程阻塞。
- 越权效果（allowedEffects 外）→`forbidden_effect`，步骤仍计入 executed。
- `executed` 只由 `action_finished` 组成，`executedBy: 'bridge'`，并补 `before`（动作前最后一次 observed）与 `after`（动作后下一次 observed）；只有 started 的步骤记 `unknown`，同样计入，不得重发。token 用 `addTokens` 累计。
- abort→`cancelled`，超过 `budget.timeoutMs`→`timeout`：先 SIGTERM，`killGraceMs`（默认 3000）后 SIGKILL；**无论哪条路径（含读取异常），都在 `finally` 中等待 `exited()` 后才返回**。
- `createLineProcessSpawner`：node:child_process，stderr 排空丢弃；自写行切分，单行超过 4 MiB 截断（随后解析失败），防止内存失控；程序不存在时 `exited()` 也会返回。

## 接入说明（给 A6/A7）

- A7 在 main.swift 注册：`if args.positional.first == "agent-bridge" { AgentBridgeCommand.run(args) }`。
- Runtime 侧：`createAgentBridge({ cli: <2ndscreen 路径>, spawn: createLineProcessSpawner() })`，在 `session.withExclusiveActor('bridge', grant => bridge.explore(req, grant))` 内调用；explore 返回即表示子进程已退出，可收回动作权。
- 修复场景请填 `usageContext: { purpose: 'repair', reason: … }`（协调者已安排 recovery.ts 填写）。
- 成功与否仍以 `workflow.verifyUnit` 为准；`status: 'finished'` 只表示模型认为完成。

## 未验证项与已知限制

- 未在真实 App 窗口上跑过完整探索（按要求不操作 BOSS、不调用模型）；真实动作/截图路径只经单元测试的假屏幕与错误路径端到端验证。
- 现有 `ChatCompletionsModel` 不返回 usage，token 全为 unknown；设置 `maxTokens` 会让探索只能做一次模型调用。要真实计数需扩展 Model.swift（不在本任务范围）。
- 模型请求是同步 HTTP（最长 60 s 超时）；请求中收到 SIGTERM 会立即写 cancelled 并退出，该请求的 token 记 unknown。
- 效果分类是保守的启发式：所有 Enter 都视为提交（包括菜单中选项的 Enter），所有点击都视为 navigation（不会是 artifact），因此 `allowedEffects` 只有 `artifact` 的单元（如 persist_candidate）无法用 Bridge 探索。
- 子进程若把 stdout 继承给孙进程，进程退出后读取可能不结束；Swift bridge 不派生子进程，未处理此情况。
- 窗口几何的 `scale`/`displayId` 在 CLI 中按窗口中心所在显示器读取；`processStartedAt` 未填。
