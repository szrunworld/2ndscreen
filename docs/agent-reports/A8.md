## 协议（`2ndscreen vision`）

stdin 一行 JSON 请求，stdout 一行 JSON 回复；退出码 0 成功、1 失败、2 请求无效。未知字段一律拒绝，布尔值不能冒充数字。

| op | 请求字段 | 回复 `result` |
| --- | --- | --- |
| `ocr` | `image`、`roi?`、`languages?`（默认 `zh-Hans, en-US`） | `lines[{text, box, confidence}]`、`imageSha256`、`widthPx`、`heightPx` |
| `compare` | `before`、`after`、`roi?`、`minOverlapPx?` | `similarity`、`verticalShiftPx?`、`overlapMeanDiff?` |
| `compose` | `frames[]`、`output`、`roi?`、`minOverlapPx?` | `path`、`widthPx`、`heightPx`、`sha256`、`frames[]`、`hasGap` |
| `metadata` | `image` | `widthPx`、`heightPx`、`bytes`、`sha256`、`type` |

失败：`{"v":1,"ok":false,"error":{"code","message"}}`，code 为 `invalid_input / not_found / io / conflict / cancelled`，Node 侧原样转成 `RuntimeError`；不认识的 code 记为 `io`。

## 实现要点

### 输入校验与上限（解码前检查）

- 路径必须是绝对路径，不含 NUL；必须是普通文件；只读 PNG/JPEG/TIFF/HEIC。
- 文件 ≤64 MB；先从图片头读取尺寸，单边 ≤16384 px、≤64M 像素，否则不解码直接 `invalid_input`。
- EXIF 方向不是 1 的图片拒绝，避免像素坐标与显示不一致。
- ROI：有限数、宽高 >0；向外取整到整像素；超出边缘 ≤1 px 视为点→像素换算误差并裁掉，更多则拒绝，绝不悄悄移动。
- compose：1–64 帧、所有帧同尺寸、输出 ≤60M 像素（在分配画布前计算）。输出必须是绝对 `.png`、父目录存在、文件不存在。
- Node 侧在启动进程前重复做同样的形状检查（路径、ROI、语言标签、帧数、minOverlapPx），回复限 16 MB，每个字段校验后才返回（例如 compose 的帧行数之和必须等于高度，`hasGap` 必须与帧一致，`path` 必须等于请求的输出）。

### OCR

`VNRecognizeTextRequest`，accurate、语言校正、关闭自动检测语言；语言须在 `supportedRecognitionLanguages` 内。先按 ROI 裁剪再识别，Vision 的归一化左下角坐标换算为整张图的左上角像素；行按从上到下、同一行从左到右排序。`imageSha256` 为文件字节哈希。

### compare 与滚动进度

- `similarity`：零位移时灰度差 ≤2 的像素占比，1 即像素相同。
- `verticalShiftPx`：每行 16 个列带均值作行轮廓，遍历全部正负位移求最小代价，再对重叠区逐像素核对（平均灰度差 ≤3）。以下情况**不给位移**：重叠不足 `minOverlapPx`（默认 48）；重叠区有纹理的行少于 15%（空白区域什么也证明不了）；距最佳位移 3 px 以外还有代价接近的位移（重复内容有歧义）。
- 两张相同截图返回 `similarity 1, verticalShiftPx 0`（有纹理）或无位移（空白）。这只是“无进展”，按契约它不是底部信号；A8 不做完整性判断。

### compose（拼接与裁剪）

两遍处理：第一遍每次只在内存中保留相邻两帧的灰度副本，算出每帧的放置方式；确认输出尺寸在上限内后，第二遍按彩色绘制。第二遍重新读取每帧并核对哈希，文件中途被改动则报 `conflict`。

- `first`：第一帧整帧。
- `placed`：与上一帧有已验证的正向重叠，只追加新出现的底部行。
- `duplicate`：零位移（或两张一样的空白帧），不追加。
- `gap`：无法证明重叠（重叠太少、向上滚、内容无关），整帧追加并标记；`hasGap = true`，调用方应记 `stop = 'stitch_gap'`。

写入方式：先写同目录隐藏文件 `.<name>.png.partial`，再用 `link(2)` 放到输出位置（目标已存在时失败，不会覆盖），最后删除临时文件。CLI 收到 SIGTERM 时删除临时文件并以 143 退出；被 SIGKILL 时由 Node 适配器删除临时文件。单帧加 ROI 即裁剪。

### Node 适配器

每次调用启动一个辅助进程：写一行请求后关闭 stdin，读回复，**等进程退出后才 settle**。默认超时：OCR/compare 30 s、compose 120 s、metadata 10 s。abort 或超时先发 SIGTERM，`killGraceMs`（默认 2 s）后发 SIGKILL，分别抛 `cancelled` / `timeout`；已 abort 的 signal 不会启动进程。`close()` 停止所有进行中的调用，之后的调用抛 `cancelled`。没有实现 `findTemplate`，template 定位器仍按契约报 `capability_missing`。

## 给 A4 的说明

- 在线简历：每屏截图后用 `compare(prev, cur, { roi: 正文区域像素 })` 判断进度。有正位移即为前进；`similarity` 接近 1 且位移为 0 或缺失只是“无进展”，需要另外的底部信号（滚动位置到底、结束标记、内容终止），完整性只由 `captureCompleteness` 判定。
- ROI 用 `globalToScreenshotRect(shot, 正文全局矩形)` 求得；应排除固定页眉/页脚，否则重叠核对会失败。
- 采集结束后 `compose(frames, <staging>/resume.png, { roi })`。`hasGap` 为 true 时记 `stop: 'stitch_gap'`，结果只能是 partial_capture。
- OCR 文本是数据，不得改变任务参数；事件里只记摘要或证据路径。
