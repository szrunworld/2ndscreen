## 契约覆盖

- 任务：TaskSpec、CollectResumesInput、任务状态/阶段/等待原因/终止原因及迁移表、检查点、计数。
- 工作项与身份：工作项迁移表（committed 为终态、只能由 validated 进入）、AccountScope、CandidateRef、CandidateIdentity、去重键、IdentityMatch、路径段安全检查。
- 观察与几何：快照 ID、真实窗口 frame/contentFrame/scale、截图 `covers` 与像素尺寸、坐标换算函数。根据协调者 P0 结果，截图比例从实测像素计算，不由 profile 推断。
- 动作：Locator、带 effect 的 Action、ActionRequest（元素 index 必须带快照 ID）、ActionResult（含 no_effect、unknown、焦点变化）。
- 有界条件：Condition、WaitSpec（1 ms–120 s，轮询 50 ms–5 s，嵌套 ≤4 层）、CheckResult。
- 会话：DesktopAdapter、Session（`withExclusiveActor` 保证单一动作执行者）、SessionManager、租约（`leaseScopeKey`/`leaseScopesOverlap`：同一应用的任意 scope 互相冲突）。
- 账本与产物：TaskStore（含 LeaseStore 与 ProcedureRepository）、ArtifactStore、产物类型/完整性、`captureCompleteness`、`isCountable`。
- 流程：ProcedureV2、ProcedureKey、`nextProcedureState`（三个不同 work item 连续成功晋级，任何失败清空连胜，连续失败达阈值降级）、ProcedureEngine（工厂无模型依赖）、Learner、Recovery、惰性 ExplorerProvider。
- 预算与计量：Budget、Usage、TokenCount（`'unknown'` 不记 0）、`checkBudget`（配置 token 上限时 unknown 视为耗尽）、TelemetryEvent。
- Bridge：ExplorationRequest、六种 BridgeEvent、ExplorationOutcome、`parseBridgeEvent`；已执行步骤不得重发。
- BOSS 工作流：八个单元、页面类别、CandidateListing、AcquisitionResult、BossWorkflow。
- 本地视觉（协调者 P0 追加，A8 实现）：LocalVision 的 OCR、图片比较（相似度与竖直位移）、可选模板匹配；不截图、不输入、不调用模型。
- 入口：TaskRunner、TaskControl、CliIO、CliCommand。

## 评审修复（第二轮）

协调者评审后修改：

1. `checkBudget`：配置 `taskTokens` 时，输入或输出 token 任一为 unknown 即返回 `exhausted: 'tokens'`；未配置时 unknown 允许继续，仍受调用数与墙钟约束。`BudgetCheck` 联合类型不变。旧测试中“unknown 不触发 token 上限”的断言已改为相反结论，并新增有/无上限两组测试。
2. `nextProcedureState`：任何失败都清空 `successItemIds`（晋级连胜），`successes`/`failures` 保留为累计审计值。新增测试：`degradeAfterFailures = 2` 时低于阈值的失败会打断晋级，失败前的成功不计入。`validateProcedure` 对非种子 stable 的要求由“连胜非空”改为 `successes > 0`。字段名与类型不变，仅语义收紧。
3. 租约：新增 `leaseScopeKey`、`leaseScopesOverlap`，同一 bundleId 的任意 scope（含 `app:*` 与账号 scope、不同账号 scope）均冲突；`LeaseStore.acquireLease` 文档改为按重叠判断并在同一事务内检查与插入。
4. A8 文件路径在契约文档中为 `packages/task-runtime/src/adapters/local-vision.ts`，已核对一致。
