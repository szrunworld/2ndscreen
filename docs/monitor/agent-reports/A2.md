## 变更

### 1. 写操作标志拆分

`command_result`（schema + `CommandResult`）与 `ActionResult` 的 `gui_write_performed` 拆成：

- `navigation_performed`：只改变本机界面的操作（打开会话、切页签/筛选、滚动、关闭弹层、在搜索框输入）。
- `outbound_action_performed`：对候选人或第三方可见的动作（发送、确认、提交转发、点击求简历/换电话、代填并提交）。
- `externally_visible_side_effect`：可能产生了对方可见的副作用（对外动作一定算；只打开未读会话产生已读回执也算）。

规则（`check_result_rules`，schema `allOf` 同步）：

| 条件 | 规则 |
| --- | --- |
| `execution_mode=verify_only` | `outbound_action_performed=false`，允许导航 |
| `status=cancelled` | `outbound_action_performed=false`（见下方"决定"） |
| `status=expired` | 三个都为 false |
| `outbound_action_performed=true` | `externally_visible_side_effect=true`（新增不变式） |
| 白名单关闭 / 限额 / 暂停 / 依赖未满足 | handler 不调用 driver，三个都为 false（文档约定；ActionResult 默认值即全 false） |

`ActionHandler` 文档字符串改为：verify_only 允许导航，不允许对外动作，打开未读会话时如实设置 `externally_visible_side_effect`。`states.py` 的 `running → cancelled` 注释、contracts.md 8.2 状态图、api.md 3.4 取消、`/commands/{id}:recheck` 与 `command.json` 的 verify_only 描述同步更新。

**三个标志在线上必填**（schema `required`，`CommandResult` 无默认值）：缺省 false 会把"忘了填"当成"没有对外动作"，进而允许取消。`ActionResult` 内仍默认 false，方便处理器在前置检查失败时直接返回。

### 2. 账户不可读

contracts.md 第七节新增"账户来源"、api.md 3.1 改写，openapi `account-binding` 与 `device_heartbeat.account_id` 描述同步：v1 的 `account_id` 来自安装时的绑定，Monitor 不从界面读取；`heartbeat.account_id` 是绑定账户，不是观察到的账户；与服务端绑定不一致只说明配置问题。`account_mismatch`（以及暂停原因 `account_switched`）保留，v1 只在有证据时使用（例如界面出现账户切换提示），目前没有检测手段，列入 N 待验证。没有改任何 schema 结构。

### 3. 定位器语义

追认 C 的实现：`Locator.text` / `text_contains` 在规范化（去方向控制符、NFKC、合并空白、去首尾空白、区分大小写）后匹配 `Element.text`、`label`、`value` 任一；仍要求唯一命中，零个/多个分别抛 `TargetNotFoundError` / `TargetAmbiguousError`。写入 `driver.py` 的 `Locator` 与 `Element.text` 文档字符串、contracts.md 第十节。

### 4. 版本与记录

版本号三处改为 0.2.0；contracts.md 第十三节加裁决三行与 0.2.0 变更记录；`monitor/uv.lock` relock（仅版本号）。

## 决定（需要协调者知悉）

- **cancelled 规则冲突**：任务描述同时要求"cancelled 时三个标志都为 false"和"running→cancelled 仅限 outbound_action_performed=false"。running 中已导航（打开会话）再被取消时，两条不能同时成立。已通过 ask 提问（msg_22a4dedca077），协调者裁决采用方案 A：cancelled 只要求 `outbound_action_performed=false`，`navigation_performed` 与 `externally_visible_side_effect` 如实记录；expired 三个全 false（只从 queued 进入）。
- 新增不变式 outbound ⇒ externally_visible，以及三个标志在线上必填、ActionResult 内默认 false：同一次 ask 中协调者已同意。
- `executed_at` 在 cancelled 时仍必须为 null（沿用 0.1.x）。导航后被取消的结果因此是 `executed_at=null` + `navigation_performed=true`，含义是"动作没有执行，但动过界面"。
