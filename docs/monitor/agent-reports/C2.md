## 一、CliFailure 改为普通异常类（J.md 第五节第 5 条）

- 原因已复现：旧的 `@dataclass(frozen=True) class CliFailure(Exception)` 穿过 `contextlib.contextmanager`
  写的 `with` 时，外层拿到的是 `FrozenInstanceError`，原异常丢失。
- 现在是普通 `Exception` 子类，构造签名不变（`kind, message, argv=(), exit_code=None, payload=None, stderr=""`，
  位置参数和关键字都可用），字段经只读属性暴露（赋值抛 `AttributeError`），`argv` 统一转成 tuple。
  另外补了 `__reduce__`，pickle 后字段齐全。
- 不再有 dataclass 的 `__eq__`。仓库里没有按值比较 CliFailure 的代码。
- driver 内其他异常类：没有了。其他 frozen dataclass（`CliOutcome`、`Raw*`、`Call`）都不是异常；
  契约里的 Driver 错误类型是普通异常类，不受影响。
- 测试（`test_driver_cli.py`）：在 contextmanager 的 `with` 里抛出，外层仍是 `CliFailure`，字段都在，
  且带 `__traceback__`；contextmanager 里 `except ... raise` 后外层拿到的是同一个对象；只读；pickle。

## 二、错误分类补收 window release 文案

- `has no matching window on screen` → `window_lost`（WindowLostError）。文案取自 2ndscreen 源码
  `AgentScreens.swift` 的 `releaseWindows`，与 J 在 `bootstrap/screen.py` 里识别的一致。
- 新样例 `cli-samples/window_release_gone.json`。**这份不是实测**：要采集它需要新建一块 agent 屏幕，
  这会改动用户的显示器布局，所以按源码文案构造，`note` 和 README 里都写明了。
- 其他样例里还没分类的文案逐个核对过：`is already running`、`the app refused to move its window`、

  `type needs --value`、参数缺值。它们都是调用错误或应用拒绝，归 `cli_failed` 是对的，没有改。
  `N window(s) refused to move` 也是 `cli_failed`，已加进源码文案测试。

## 三、Driver 层剔除附件 PDF 预览子树（H1 接口请求，status.md 已同意）

新模块 `driver/pdf_preview.py`（`is_pdf_preview`、`hidden_positions`、`strip_pdf_preview`）。

**规则**（依据 capabilities.md 1.4 和 attachment_entry#4）：

1. 容器：基础角色 AXWebArea，label 经 NFKC 后含 "PDF"（不区分大小写）。这和 H1 的 `is_pdf_preview` 一致。
2. 只判定排在容器之后的元素，因为深度优先展开时后代总在祖先之后：
   - 有树信息时，沿 parent_index 往上能走到容器的就剔除。CliDriver **总会**解析 CLI 的 tree 文本来做这一步，
     与 include_tree 无关。所以滚出可见区、框不在容器内的文字层也能剔掉。
   - 没有树信息时（B 的夹具不带树），元素框完整落在容器框内（容差 1 点）的剔除。这里不用"中心点落在框内"，
     否则容器后面那个铺满窗口的 AXGroup（attachment_entry#4 的 173）也会被误删。
3. 容器本身保留，剔除后重新从 0 连续编号（契约要求 index 等于位置），parent_index 同步换算。

**各处行为**：

- `CliDriver(hide_pdf_preview=True)`：`state()` 剔除。剔除后快照 index 与 CLI index 不同，所以 CliDriver
  记了"快照位置 → CLI index"的映射。click/type/scroll 的 `--index`、执行前的复核、执行后核对 CLI 回报的元素、
  `ax_press` 动作检查，都按映射换算。复核读取用的是与最近快照相同的剔除方式。新增的 `convert_state()` 同时返回
  快照和映射；`snapshot_from_state()` 签名保持兼容，多了 `hide_pdf_preview` 参数，默认 True。
- `FakeDriver(hide_pdf_preview=True)`：回放时同样剔除。定位、Element 目标校验、Advance 的 target 匹配
  用的都是剔除后的编号。
- 录制：`CliDriver.record_step` 不管构造参数，**始终**剔除。`FixtureRecorder.add_step` 写入前也会再剔除一次，
  所以拿任何快照录制，都不会把文字层写进夹具。如果这一步改变了元素位置，标注里的
  `conversations[].element_index` 和 `is_new_application` 会按新位置换算。标注引用了被剔除的元素时抛
  `ValueError`。`x_` 扩展标注不换算。
- `hide_pdf_preview=False` 只给测试和排查用。`test_driver_fake.py` 的"B 夹具逐项回放"改为在关闭剔除的情况下比对。

**测试**（`test_driver_pdf_preview.py`，22 个）：

- attachment_entry#4 经 `FakeDriver.state()` 后：没有『切图』和文字层占位，『PDF预览』容器还在，编号连续，
  容器框外的工具栏图标、关闭按钮和窗口按钮都保留。其他步骤与夹具逐项一致。关闭剔除后与夹具一致。
  预览里的控件定位不到；关闭按钮的 index 从 172 变成 170，点击和 Advance 都正常。
- 规则本身：树规则按祖先关系判定，不看几何位置（滚出框的后代会剔除，浮在框上的非后代会保留）；几何规则；
  显式父映射优先，缺的元素回退几何规则；没有预览时原样返回。
- CliDriver：模拟一份带预览和 tree 的 CLI 输出，电话、邮箱、『切图』都不在快照里。点容器后面的元素时，
  发给 CLI 的是原 index（7），定位器也一样换算；ax_press 检查用的是换算后的 actions。关闭剔除后快照完整。
  没有 tree 时回退几何规则。关闭剔除时 `record_step` 仍然剔除。
- 录制：剔除后标注换算正确，契约校验通过；标注引用被剔除元素时报错，且这一步不会写入。

## 五、未覆盖与已知限制

- CLI 原始 JSON（含 tree 文本）仍会短暂经过进程内存，因为 CLI 本身没有排除子树的参数。剔除发生在转成
  Snapshot 时，之后快照、调试输出、录制都不再带文字层。CliFailure 的 payload 只在失败时存在，state 失败时没有元素。
- 几何回退规则只在 CLI 不输出 tree 时才会用到。真机输出一直带 tree，但如果 tree 缺失，滚出可见区、
  框在容器外的文字层会漏掉。B 的夹具已经删掉文字层，所以对回放没有影响。
- 以上都没有在 BOSS 客户端上真机验证；预览容器的 label（『PDF预览』）来自 B 的录制。
