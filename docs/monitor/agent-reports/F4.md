## 二、变更

1. **一致性白名单清空**：`KNOWN_YAML_GAPS` 和 `KNOWN_SECURITY_GAPS` 都改成空字典，注释写明了以后出现新缺口时怎么登记。服务端导出的响应码、认证方式现在和 0.3.2 yaml 完全一致。
2. **`ResumeDocument.candidate_case_ids`**：在 `resume_documents.ResumeDocument` 和 `cases.ResumeDocument`（CaseDetail 内嵌）两处都加了 `list[str] = []`。`document_record` 用 `candidate_case_ids(row)` 填值，来源是写入时保存在 `link_json` 里的候选列表，去重并保持原顺序。只有 `link_status=needs_manual` 时返回候选；已关联的文档、自动关联的文档和品牌化版本都返回 `[]`。
3. **`ManualCommandCreated.scheduled_for`**：工作时段外顺延时等于 `command.issued_at`（下一个时段的开始时间），其他情况为 `null`。
4. **getPolicy 认证**：路由依赖直接改成 `mail_endpoints.require_policy_reader`（控制台读写；设备和 serviceToken 只读）。删掉了 `policy.require_console_or_device`，也删掉了 `create_app` 里的 `dependency_overrides`。`listResumeDocuments` 原本就接受 serviceToken，现在 yaml 也已列出。PUT 策略和 `:link` 仍然只接受控制台，有测试覆盖。
5. **搜索受工作时段约束**（以契约 0.3.2 openapi `createSearchRun` 和 api.md 为准）：
   - 工作时段外 `POST /search-runs` 返回 409 `policy_blocked`，`errors[]` 为 `{path: "policy.work_hours", code: "outside_work_hours"}`。不顺延，不建搜索任务，也不生成指令。
   - 每日上限改用 `PolicyStore.count_outbound`，和问候、求简历共用同一套统计：指令表里 execute 模式的指令，已取消或已过期且没有结果的不计。原来是按 `search_runs` 表计数，现在已删除对应的 `SearchStore.count_between`。
   - 原有的错误码（`action_not_allowed` / `paused` / `device_paused` / `rate_limited` / `daily_limit_reached`）不变，所以没有换成 `ctx.policies.gate`（它的原因码不同）。测试夹具 `search_policy` 的默认工作时段改为 `ALL_DAYS`（每天 09:00–18:00，上海），可控时钟的起点正好落在时段内。原来那个把时区改成 UTC 的用例，改为显式给出 UTC 全天窗口。
6. **人工输入有效期**：登记 `human_input_required` 时，有效期优先取 `payload.expires_at`；为空时取 `observed_at + INPUT_REQUEST_TTL_SECONDS`（契约常量，600 秒）。原来是从服务端收到事件的时间算起，现在改了。设备离线后补报的旧请求可能一登记就已过期。`provide_input` 指令的 `expires_at` 等于这个有效期。**过期后返回 409 `input_request_expired`**：契约就是这么写的，见下面的问询记录。

## 三、取舍与遗留

- 改用指令表计数后，取消或过期且没有结果的搜索会让出名额，和其他对外动作一致。最小间隔仍按 `search_runs.created_at` 计算，所以被取消的搜索仍然占用间隔。
- 过期返回 410 需要下一版契约在 respondInputRequest 里加上 410。届时把 `LoginRelayService.respond` 里的 409 改成 410，并改测试即可。
