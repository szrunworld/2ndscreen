## 变更内容

1. **移除 forward_resume**：action 枚举、`ForwardResumeCommand` / payload / `ForwardOutput`、结果规则、策略白名单、`daily_limits` / `min_interval_seconds`、设备能力全部删除。`CONVERSATION_ACTIONS` / `OUTWARD_ACTIONS` 随之变化。contracts.md 写明"v1 不支持，名字保留以后再用"。`attachment_available` 改为可选观察，服务端不据此下发任何指令。
2. **policy**：新增 `resume_mail_timeout_days`（1–30，默认 3）、`company_mailbox`（邮箱或 null，`readOnly`，PUT 时服务端忽略）。两者在线上必填，模型里有默认值。`after_resume_received` 默认 `{action: none, wait_for_parse: true}`；按追加要求，`action` 只允许 `none`。
3. **case 状态机**：迁移表没有增删边（需要的边 0.2.0 已有），改了注释、文档与状态图：主路径 `resume_requested → resume_linked`，`resume_received` 是可选观察，`resume_requested → needs_human` 用于超时或关联歧义。新增测试锁定这几条边。
4. **邮箱**：
   - 新契约 `mail_message`（schema + `MailMessage` + `validate_mail_message`）、`mail_verification`（schema + `MailVerification` + `validate_mail_verification`）。
   - 新函数：`compute_mail_message_id`（协调者裁决的确定性主键：有 Message-ID 用 邮箱 + Message-ID，否则用 邮箱 + UIDVALIDITY + UID）、`normalize_mailbox`、`normalize_message_id`、`mail_message_key(id, status, attempts)`、`mail_verification_key`。
   - 新状态层 `MailState` / `MAIL_TRANSITIONS` / `can_transition_mail` / `require_transition("mail", …)`：pending → processed / needs_review / failed / ignored；needs_review → processed；failed → pending。
   - openapi：新增 `GET /mail-messages`（按 status、mailbox、message_id、收件时间过滤）、`PUT /mail-messages/{mail_message_id}`（协调者批准的写入口，幂等 upsert，409 分两种）、`POST /mail-verifications`、`GET /mail-verifications`。
   - resume_document：新增 `variant`（original / branded）、`derived_from`、`mail_message_id`。`ResumeDocumentCreate` 用 if/then 区分原件与品牌化版本。`link_method` 的 `forward_record` 改为 `resume_request`。`resume_document_key` 的第一个参数改为来源标识（原件用 mail_message_id，品牌化版本用 `branded:<derived_from>`）。
5. **搜索快照**：卡片改为 `{result_ref, position, fields[{label?, text}], masked_name?, prop_card_texts[]}`，删除 `display_name / summary / stable_candidate_id`。`position` 必须等于 `result_ref` 的序号。卡片文本两层都拒绝手机号样式的数字。coverage 与三种结局的规则没改。会话目标删除 `result_ref`，v1 搜索结果不能作为任何指令的目标；contracts.md 与 api.md 都写明了。
6. **openapi 补码**：F1 报告「0.2.0 适配」清单全部补齐（getDevice、revokeDeviceToken、pauseDevice、resumeDevice、getCommand、cancelCommand、listEvents 补 401+422；confirmAccountBinding 补 401；listCommands 补 422；ackCommand 补 403+422）。新增测试 `test_f1_response_code_gaps_are_filled` 锁定这些响应码。**F1 的 `KNOWN_YAML_GAPS` 现在可以清空**（我没有改 server 测试）。
7. **追加：换微信**（协调者转达用户确认）：`exchange_type` 枚举改为 `["wechat"]`，指令、结果、`contact_exchange_updated` 一起改，依据是 B 观察到的『请求交换微信已发送』。新增 `POST /cases/{case_id}:request-wechat`（RequiredNoteBody，响应 201 `{manual_action, command}`，ManualAction 类型 `request_wechat`），文档写明服务端不得在自动流程中生成该指令。仍不回传微信号原文。`externally_visible_side_effect` 的说明（schema、protocols、contracts.md）补充："打开会话产生的已读回执是可接受的副作用，如实记录"。
8. **版本与文档**：`__version__`、`contracts/pyproject.toml`、`openapi.yaml info.version` 三处都是 0.3.0。contracts.md、api.md 同步，第十三节新增裁决 6 行和 0.3.0 变更记录（含受影响任务）。

测试向量：合法 42 个、非法 59 个（0.2.0 时合法 37 个、非法 41 个）。新契约都有合法与非法样本；删除了两个 forward_resume 合法样本，`command_wechat_exchange` 改为 `command_phone_exchange`。新增测试文件 `tests/test_mail_and_search_030.py`；`test_openapi.py` 新增 6 个测试，其中 `ResumeDocumentCreate` 的 9 种请求体用 openapi 组件加外部 schema 实际校验。

## 未覆盖项

- `ResumeDocument`、`ManualCommandCreated`、`MailVerificationRecord` 只在 openapi 里定义，没有 pydantic 模型（与 0.2.0 的 resume_document 一致）。服务端需要自己按 openapi 校验。
- schema 的 `format: email` 用的是 jsonschema 自带的宽松检查（只要求有 @），pydantic 层用 `^[^@\s]+@[^@\s]+$`，两者都不验证域名。
- `mail_message_id` 规范化时把邮箱整个转成小写。RFC 允许 local part 区分大小写，但实际邮箱基本不区分，所以按协调者给的公式处理了。
- 搜索卡片的真实文案（尤其是道具卡相关文案）没有在真机上观察过（capabilities.md 1.6 写明输入关键词后的结果未观察到），向量里的卡片文本是合成的。

## 对后续任务的接入说明

- **G（邮件接入）**：主键用 `compute_mail_message_id(mailbox, message_id, uidvalidity=, uid=)`。落盘后 `PUT /mail-messages/{id}`（status=pending，Idempotency-Key 用 `mail_message_key(id, "pending", 0)`）。消费前后用 `can_transition_mail` 检查迁移，未达上限的失败保持 pending 并把 attempts +1。写简历原件时带 `variant=original`、`mail_message_id`，关联用 `link.method=resume_request` + 对应 request_resume 的 `command_id`，Idempotency-Key 用 `resume_document_key(mail_message_id, sha256)`。核对完成后用 `validate_mail_verification` 自检再 `POST /mail-verifications`：outcome 为 ok / issues_found 时必须带齐 7 个检查项；超时提醒放在 `overdue_resume_requests`，不影响 outcome。
- **R（品牌化）**：`POST /resume-documents` 时 `variant=branded`、`derived_from=<原件 doc_id>`，不带 mail 和 link，Idempotency-Key 用 `resume_document_key("branded:" + derived_from, sha256)`。
- **F2**：`resume_requested` 超过 `policy.resume_mail_timeout_days` 未关联 → `needs_human`（`needs_human_reason=resume_mail_timeout`）。只在 `request-wechat` 时生成 `request_contact_exchange`（`exchange_type=wechat`），自动流程里永远不生成。`after_resume_received.action` 只会是 none。
- **H2**：快照卡片按出现顺序原样填 `fields`。只有界面上确有可见标签时才填 `label`。打码姓名同时放在 `fields` 和 `masked_name` 里。道具卡相关文案放 `prop_card_texts`，不要点击。`result_ref = f"{search_id}:item_{position}"`。
- **H3**：只处理 `exchange_type=wechat`。已发出请求的判断依据是『请求交换微信已发送』系统提示，加上『换微信』置灰。
- **E**：`contact_exchange_updated` 的 `exchange_type` 只能是 `wechat`。`attachment_available` 仍可以上报，但只是可选观察。
