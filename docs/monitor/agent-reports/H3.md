## 三、实现概要（`contact_exchange.py`）

复用 H1 的 `ConversationActionHandler` 骨架：白名单 → `open_conversation()`（姓名 + 岗位 + hints 全匹配，歧义不点击，打开后核对表头）→ 读状态 → 执行 → 等待 → `session.result()`。PDF 文字层由 `read_view()` 剔除（D2b/C2 之后 driver 层也已过滤）。

**按钮可用 / 置灰**（`exchange_button`）：按钮条里文案恰为『换微信』的 StaticText，其中心落在一个 57×24（容差 50–64 × 20–28）、无 label 的 AXGroup 里 → enabled，点击目标是该 AXGroup；没有 → disabled；找不到 / 多个 → missing / ambiguous。规则来自 capabilities.md 1.3（CLI 不输出 enabled，B 对照截图得出）。

**状态判断**（`read_exchange_state`），只认夹具上观察到的三种组合：

| 提示『请求交换微信已发送』 | 『换微信』 | 『换电话』 | 判定 | 动作结果 |
| --- | --- | --- | --- | --- |
| 有（聊天区居中） | 置灰 | 任意 | pending_acceptance（#1） | skipped_precondition，`exchange_state=pending_acceptance` |
| 无 | 可用 | 任意 | not_requested（#0） | 继续点击 |
| 无 | 置灰 | 置灰 | unavailable（#2，招聘方未回复） | failed / `target_not_found` |
| 其他组合 | | | unrecognized | unknown / `unreadable`，不点击 |

"已交换"没有夹具依据（#3、#4 的筛选都是『暂无牛人』），**未实现识别，也不猜**：它会落在 unrecognized（或者，如果已交换后界面与 #1 相同，会被当成 pending_acceptance，见第五节第 5 条）。

**置灰时的 reason**：契约没有"前置条件不满足"的值。选 `target_not_found`（契约释义"找不到目标会话或按钮"：可点击的『换微信』不存在），`reason_detail` 与 evidence 写明"『换微信』置灰（疑为招聘方尚未回复）"。服务端如需区分，可看 `observed.before` 里的 `wechat_button_disabled` / `phone_button_disabled`。

**无法识别时的 reason**：`unreadable`（"界面读不出"），状态必须是 unknown 而不是 failed，因为可能已经请求或已交换，不能让上游重试。

**执行与确认气泡**：在 `session.outbound()`（→ `ctx.outbound()`）里点击外层 AXGroup，然后 `Waiter` 轮询（0.5 秒间隔，上限 10 秒，注入时钟）：

- 出现提示 → succeeded，`exchange_state=requested`。前置检查已排除"以前就有提示"，所以这里的提示一定是本次产生的。
- 只有一个弹窗，并且文案匹配 `/(交换|换)微信/`、不含『电话 / 手机』、按钮只有『取消』加恰好一个『确认』或『确定』→ 在 outbound 里点一次该按钮，重新等待 10 秒；确认后同一气泡还在 → 继续等，不再点。
- 其他任何弹窗 → unknown / unknown_dialog，不点任何控件。超时 → unknown / timeout。

**output**：succeeded → `requested`；skipped_precondition → `pending_acceptance`；unknown → `unknown`；failed（含白名单关闭）不带 output。verify_only 确认已请求时 succeeded 也报 `requested`（与 run 成功一致；当前界面是待同意，evidence 里有按钮状态）。

**Fact.code**：`wechat_exchange_notice_present / absent`、`wechat_button_{enabled,disabled,missing,ambiguous}`、`phone_button_{…}`、`wechat_exchange_state_unrecognized`、`wechat_confirm_dialog`、`wechat_confirm_clicked`，外加 H1 的会话类 code。

**不交换电话**：只查找文案为『换微信』的按钮；『换电话』只读取状态用于判断，测试断言它从未被点击；确认白名单拒绝提到电话 / 手机的气泡。

## 四、未覆盖项

- 没有在真机运行；点击后的全部界面变化来自派生步骤。
- 已交换、已拒绝、请求过期的界面没有观察到，不识别（unknown / unreadable）。`contact_exchange_updated` 由 E 负责，本动作不产出事件。
- 聊天记录很长、『请求交换微信已发送』滚出可见区时：如果『换微信』仍置灰而『换电话』可用 → unknown / unreadable（安全，但需人工确认）；不会滚动查找（capabilities.md 1.2 后台滚动无效）。
- 登录失效、验证码、风控页沿用 H1 的处理（普通 AXButton / Sheet → unknown_dialog，其他形态 → timeout）。
- `account_mismatch`：契约 v1 没有检测手段，未使用。
