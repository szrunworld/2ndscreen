## 三、实现概要

### 公共流程（`common.py`）

`ConversationActionHandler.run`：白名单检查（关闭 → `failed/action_not_allowed`，不调用 driver）→ `ConversationSession.open_conversation()` → 子类的前置检查与执行 → `session.result()`。

1. **读取**：`read_view(driver)` = `state()` 后立即按几何位置剔除『PDF预览』AXWebArea 内的全部元素（只看容器的角色与 label，不读其中文字），之后所有定位、弹窗识别、evidence 都只用剔除后的视图。
2. **弹窗**：`detect_blockers()`。依据是 B 的全部夹具：会话列表和会话详情页上没有任何"普通" AXButton（窗口关闭 / 缩放 / 最小化除外），出现普通 AXButton 的只有确认气泡、PDF 预览、在线简历弹层。有遮挡时不点任何控件，返回 `unknown_dialog`，弹窗文案（脱敏后）写进 evidence 和 `observed`。
3. **定位**：会话行 = 宽 300–460、高 20–120 的无 label AXGroup，且行内至少有两个带 label 的 AXGroup（姓名、岗位）。行内某个元素的 label 或 value 规范化后**完全等于**姓名、岗位、每个 hint，才算命中。多行命中 → `target_ambiguous`，不点击；当前视图没有命中 → 先点左侧『消息』（如果没有会话列表），再依次切『新招呼 / 沟通中 / 全部』，每次最多等 2 秒；仍然没有 → `target_not_found`。
4. **打开**：点击该行（导航），然后轮询直到表头姓名与『沟通职位：』右侧的岗位都一致。行内姓名左侧有数字角标就视为未读，打开后 `externally_visible_side_effect=true`（已读回执）。
5. **等待**：`Waiter(clock)` 每轮重新 `state()`，两轮之间 `clock.sleep(0.5)`，上限 10 秒。clock 是注入的 `monitor.core.Clock`（now / sleep），测试注入 `ManualClock`，没有固定 sleep。
6. **结果**：`session.result()` 统一修正状态。对外动作之后的失败一律改判 `unknown`（动作可能已经生效，不能让上游重试）；verify_only 里除 `verification_failed` 之外的失败也改判 `unknown`（无法判断）。三个标志按会话记录如实填写，`outbound ⇒ externally_visible`；evidence 删除手机号、微信号、邮箱，候选人姓名换成『[候选人]』，每条不超过 500 字，最多 50 条。

对外动作一律放在 `session.outbound()` 里，它会转给 `ctx.outbound()`（D2b 的 `ExecContext`）。只有导航（打开会话、切页签）放在外面。verify_only 只调用导航类点击，不调用 `type_text` / `key` / `outbound()`。

### send_greeting（`greeting.py`）

打开会话 → 聊天区已有同一文本的我方消息 → `skipped_precondition/precondition_already_done`（防止重复送达或崩溃后重复问候）→ 先确认『发送』存在 → 在 `outbound()` 里输入 `payload.text`，重新读取，点击最新快照里的『发送』→ 等待聊天区出现该文本的我方消息 → succeeded；看不到 → `unknown/timeout`，不重发。`executed_at` 是开始输入的时间。

### request_resume（`request_resume.py`）

打开会话 → 聊天区居中有『简历请求已发送』→ `skipped_precondition`（不看按钮状态）→ 点『求简历』（对外动作）→ 等待结果：

- 出现提示 → succeeded，`executed_at` 是点『求简历』的时间（供邮件关联用）。
- 只有一个弹窗，并且同时满足以下条件：文案匹配 `/确定向牛人(请求|索取)(附件)?简历/`，按钮只有『取消』『确认』，『确认』恰好一个 → 点一次『确认』（对外动作），重新等待 10 秒。确认后如果同一个气泡还在，就继续等，不再点。
- 其他任何弹窗（包括确认后出现的第二个气泡）→ `unknown/unknown_dialog`，不点任何控件。
- 超时 → `unknown/timeout`。

### 注册（`__init__.py`）

`create_handlers(*, clock=None) -> list[ActionHandler]`，目前返回 send_greeting 和 request_resume 两个处理器。H2、H3 的注册点见第七节，不需要改本文件。同一个 action 注册两次会抛 `ValueError`。

## 四、未覆盖项

- 没有在真机运行。真实发送或请求后的界面变化（消息出现的位置与时机、『送达』何时出现、确认气泡是否存在及其文案、系统提示是否原样出现）全部来自派生步骤，见第五节。
- 登录失效、验证码、风控页没有专门识别：它们只要以普通 AXButton 或 Sheet / Dialog 呈现，就会按 `unknown_dialog` 处理；用其他形态呈现时，动作会以 `timeout` 结束。`login_required` 和 `captcha` 这两个 reason 本任务没有产出（K / E 负责识别登录页）。
- 列表跨页签的歧义：只要某个视图里唯一命中就使用它，不会再去其他页签查找同名同岗位同 hints 的会话。
- 『全部职位』下拉如果筛到了其他岗位，目标就不可见，会返回 target_not_found；不会去切换职位筛选。
- 会话列表只暴露约 10 行，后台滚动无效（capabilities.md 1.2），所以不滚动查找。
- `account_mismatch`：契约 v1 没有检测手段，本任务没有使用。

## 六、接口请求 / 需要协调者知悉

1. **PDF 文字层在 Driver 层就该丢弃（给 C，非阻塞）**。H1 在拿到快照后、任何文本访问之前剔除 PDF 预览区域，所以动作代码、evidence、observed 都不会碰到这些文字。但 `Driver.state()` 返回的 `Snapshot` 里仍然有它们，会进入进程内存，CliDriver 的调试输出也可能带出来。建议 C 在 CliDriver / FakeDriver 的 state 里按『PDF预览』AXWebArea 过滤子树（或提供 `exclude_regions` 参数），这样"绝不读取"才是在源头成立。
2. **hints 的稳定性（给 E / F2，非阻塞）**。hints 要求完全相等。B 标注里的 hint 是列表时间（例如『16:23』），第二天会变成『昨天』，届时已下发的指令就会 target_not_found。建议 E 产出事件时只放不随时间变化的 hint，或者由服务端在下发前按最近一次观察更新。
3. **问候的前置检查是本任务的取舍（给协调者确认）**。契约只要求问候"执行后读到该文本"。我另外加了一条：聊天区已有同一文本的我方消息时，返回 `skipped_precondition/precondition_already_done`，用来避免指令重复送达或崩溃重做时重复问候。如果产品上希望允许重复发送同一模板，删掉 `greeting.py` 里的这个分支即可。
4. 契约没有缺口：`Fact.code` 用的都是 snake_case 自定义值（见第七节）。

### 给 D2 / M / J

- 处理器构造参数：`clock`（`monitor.core.Clock`，用于轮询）、`timeout=10`、`poll_interval=0.5`。`__main__` 用默认的 `create_handlers()`，即 SystemClock。如果需要和 runtime 共用同一个时钟，可以改成 `--handlers` 指向一个传 clock 的工厂。
- 执行一次的最长耗时：打开会话最多 10 秒，加上切页签每次最多 2 秒，加上结果等待 10 秒（带确认气泡时再加 10 秒），总共约 30–36 秒，期间一直占着 GUI 执行权。

### 已知限制

- 仅凭『简历请求已发送』无法区分"本次请求"和"以前的请求"：verify_only 只要看到提示就回报 succeeded。run 里因为前置检查已经排除了"以前就有"的情况，所以不受影响。
- 问候按全文完全相等来匹配，模板里如果含有客户端会改写的字符（例如表情转成图片），就认不出来 → unknown。
- 弹窗文案的取法是按钮上方连续的静态文本行（行距超过 24pt 就停），多段落的复杂弹窗可能只取到一部分；这只影响 evidence，不影响"不点击"的判断。
