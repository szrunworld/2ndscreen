## 二、变更

1. **搜索算对外动作**（用户 2026-10-04）
   - contracts.md 第四节执行标志表：把"在搜索框输入关键词"从 navigation 的例子移到 outbound；新增"搜索算对外动作（0.3.2）"一段说明；第三节 search_candidates 说明同步。
   - 规则：`search_candidates` + succeeded 时三个标志都必须为 true。schema（`command_result.json` 新增一条 allOf）和模型（`check_result_rules`，ActionResult 也复用）两层都检查。失败的搜索如实填写，不加约束。
   - 向量：合法向量 `result_search_complete`、`result_search_empty_confirmed` 改为三个标志全 true；新增非法向量 `result_search_success_not_outbound`。
   - 工作时段：policy.json 的 `work_hours` 加了说明（对外动作含 search_candidates；人工换微信顺延；provide_input / verify_only 不受约束）。openapi `createSearchRun` 写明窗口外返回 409 `policy_blocked`，不顺延。contracts.md 第七节、api.md 第四节同步。
2. **F2**
   - openapi `ManualCommandCreated` 增加 `scheduled_for`：`[string, null]`、date-time，不列入 required。工作时段外人工换微信时它是下一时段的开始时间（等于 `command.issued_at`），否则为 null。
   - 写明"`issued_at` 未到不下发"：contracts.md 第三节"下发时间"、openapi `claimCommands` 说明、api.md 3.3。`requestWechatExchange` 的说明补了窗口外返回 201 并顺延的规则（按 F2b 实现）。
3. **F3**
   - 按 server `KNOWN_YAML_GAPS` 逐项给 19 个操作补响应码（`$ref` 到已有的 Unauthorized / Forbidden / NotFound / ValidationFailed）。我在本地临时把两个白名单清空、跑完再还原，确认补上的 401/403/404/422 与代码导出的响应形状全部一致。
   - `listResumeDocuments`：security 改为 consoleSession + serviceToken。`getPolicy`：在原来的 consoleSession、deviceToken 之外加 serviceToken。两者都只读，`putPolicy` 不受影响（有测试锁定）。
   - `ResumeDocument` 增加 `candidate_case_ids`（string 数组，默认 `[]`，不列入 required）。
   - 人工输入有效期：`human_input_required.payload` 增加 `expires_at`（可空，必须晚于 observed_at，模型层检查）。为 null 时服务端取 observed_at + 600 秒，导出常量 `INPUT_REQUEST_TTL_SECONDS = 600`；provide_input 指令的 expires_at 等于它。`respondInputRequest` 说明同步。新增合法向量 `event_human_input_with_expiry`、非法向量 `event_human_input_expired_at_observation`。
4. **G**：`mail_message_key(mail_message_id, status, attempts, revision=None)`。传 `revision="purged"` 时状态段变为 `<status>-purged`，与 G 的 `retention.purge_key` 逐字节一致（测试断言 `mail:<uuid>:processed-purged:0`）；其他取值抛 ValueError。contracts.md 9.2、api.md 邮件记录同步。
5. **版本**：`__version__`、`contracts/pyproject.toml`、`openapi.yaml info.version` 三处都改为 0.3.2。contracts.md 第十三节加了 6 条裁决和 0.3.2 变更记录；api.md 版本号和相关段落同步。

## 三、其他包因本版产生的失败与跟进

**server（21 failed，都在 `tests/test_openapi_consistency.py::test_operation_consistent_with_yaml`）**
- 原因：yaml 补上了响应码，`KNOWN_YAML_GAPS` 里的条目不再是差异，而这个白名单要求和实际差异"完全一致"。
- 跟进（server 任务）：
  1. 清空 `KNOWN_YAML_GAPS`，同时清空 `KNOWN_SECURITY_GAPS`（listResumeDocuments 的 serviceToken 已进 yaml）。
  2. 清空后我在本地验证过，还剩 6 个失败，都要改 server 代码：
     - `createResumeDocument`、`getResumeDocument`、`listResumeDocuments`、`postParseResult`：`cases.ResumeDocument` 模型要加 `candidate_case_ids: list[str] = []`，并从已保存的候选列表填值。
     - `requestWechatExchange`：响应模型加 `scheduled_for: datetime | None = None`，顺延时填 `issued_at`。
     - `getPolicy`：把 F2 路由依赖改成 `require_policy_reader`，删掉 `create_app` 里的 dependency_overrides，导出的 openapi 才会带 serviceToken（F3 报告接口请求 3）。
  3. 行为跟进（测试暂未覆盖）：搜索门槛改用 `ctx.policies.gate(policy, "search_candidates")`，加上工作时段检查（F3 报告"问询记录"第一条）。provide_input 的 expires_at 改为优先取事件里的 `payload.expires_at`。

**client（无新失败）**
- H2 的 strict xfail `test_actions_search.py::test_core_treats_search_success_as_outbound` 仍为 xfail，它测的是 core 的 `write_flags.success_is_outbound`，不归契约管。
- 跟进（D2d / core）：search 按对外动作计数；崩溃恢复复核搜索成功时 outbound 不再强制为 false（否则新的契约规则会拒绝这个结果）。完成后去掉这个 xfail。
- client 现有的搜索成功路径已经三标志全 true，新规则没有让任何测试失败。
- 可选：Monitor 发 human_input_required 时可以带 `expires_at`；不带时行为不变。

**mail（无失败）**
- 可选：把 `retention.purge_key` 改成直接调用 `mail_message_key(..., revision="purged")`，键不变。

## 四、取舍与待确认

- 版本号按任务要求用修订号 0.3.2。按第十二节，新增字段和搜索标志规则本该升次版本号。现在新字段都是可选的，0.3.1 的设备和服务端仍然兼容（`POST /devices` 只比较主次版本）。唯一收紧的地方是搜索成功必须三标志全 true，client 已经满足。
- `scheduled_for`、`candidate_case_ids`、`expires_at` 都做成可选，不放进 required。这样旧 server 和旧 client 的数据不会因本版失效，server 用 pydantic 的默认值导出的 schema 也能直接对上。
- 多账户时邮件接入读哪个账户的策略（G 报告接口请求 3）没有裁决，contracts.md 和 api.md 都写的是"仍未裁决"。
- F3 报告接口请求 5（控制台待办的 HTTP 接口）不在本任务范围内，没有处理。
