## 实现概要

- **装配**：`app.main.create_app(store=, clock=, settings=, console_auth=, service_auth=, bus=, policy_version=, login_qr_active=)` 的所有依赖都可以注入，默认是内存 SQLite、系统时钟、进程内事件总线。路由前缀 `/api/v1`。
- **存储**：`db.Store` Protocol 加 `SqliteStore`。会改状态的方法都在实现内部保证原子（进程内 RLock + `BEGIN IMMEDIATE`），换 PostgreSQL 时对应用事务加 `FOR UPDATE SKIP LOCKED`。迁移按 `PRAGMA user_version` 版本化，只追加不修改；单个版本失败时整体回滚，库版本高于代码时拒绝降级。表：enrollments、devices（含 mode）、account_bindings、commands、events、manual_actions、idempotency_keys。
- **认证**：设备令牌只存 sha256，吊销后返回 401；路径中的设备与令牌不符返回 403。控制台会话和服务令牌通过 `TokenAuthenticator` 注入，默认实现是固定映射（F1 不做登录体系）。
- **幂等**：按（principal，方法，路径，键）保存 2xx 响应 24 小时。同键不同请求体返回 422 `idempotency_key_reused`；同一个键的并发请求串行执行，不同键之间互不阻塞（长轮询不会挡住别人）。非 2xx 响应不保存。
- **注册重放**：设备令牌不能明文落库，所以 `POST /devices` 用同一个键重放时会**重新签发令牌并作废上一枚**。这样断网重试仍能拿到可用令牌。
- **领取**（原子）：先把租约过期且未 ack 的指令放回 pending，再把从未被领取、已经过期的指令置为 expired，然后按 seq 选出满足条件的指令：同账户、未指定设备或指定了本设备、pending、未取消、未过期、依赖已 succeeded。以下情况返回空列表：设备暂停、心跳 `needs_baseline=true`、绑定未确认、请求账户与绑定不一致、**还没有心跳或心跳账户与绑定不一致**。长轮询用代数计数的条件变量实现：新建、结果、取消、恢复、绑定、心跳都会唤醒等待中的请求。
- **结果**：校验契约，检查路径 id、`action` 和 `execution_mode` 与指令一致。只有领取过该指令的设备才能回报。重复回报时按契约归一化后比较（UUID 大小写、默认值）：相同返回 `duplicate=true` 和首次结果，不同返回 409 `result_conflict` 并带 `existing`。设备回报会覆盖服务端自行判定的 expired。
- **取消**：pending 直接置为 cancelled；已领取的指令登记 `cancel_requested`，通过心跳和领取响应的 `cancellations` 通知设备，最终状态以设备回报为准。已有结果的指令返回 409 `command_final`。每次取消记一条 `manual_actions(type=cancel_command)`。
- **事件**：用 `check("event")` 逐条校验，并要求事件的 `device_id` 与批次一致，失败的条目标为 rejected，不影响整批。按 `event_id` 去重，同一批次内重复的也算 duplicate。

## 已知限制

- 心跳会用上报的 `mode` 更新设备记录的 mode，`monitor mode` 切换后不需要重新注册。若希望模式切换必须经控制台确认，需要改这里。
- 设备卡片上的 `paused` 取"控制台暂停或设备自报暂停"；`HeartbeatAck.paused` 只反映控制台暂停。
- 吊销令牌不会释放已 ack 的指令。已领取但未 ack 的指令在租约过期后回到 pending，可以被其他设备领取。
- 事件的 `account_id` 不与设备绑定做比对，只校验契约和 device_id。
- 幂等记录超过 24 小时后不再生效。`purge_idempotency` 已实现，但没有定时调用。
- 契约 0.2.0（`gui_write_performed` 拆分）：服务端的结果校验与比较全部走 `monitor_contracts`，会自动跟随。需要同步修改的只有 `tests/conftest.py::Harness.result_body` 中写死的 `gui_write_performed`。

## 对后续任务的接入说明

- **F2（流程与策略）**：
  - 订阅事件：`ctx.bus.subscribe(handler)`。`handler` 会收到 `EventReceived`（新事件首次落库）和 `CommandResultRecorded`（指令结果首次记录，带 `case_id`、`status` 和 CommandRecord），返回值是取消订阅函数。消息在提交之后同步投递；订阅者抛出异常只会被记录，不影响 HTTP 响应和其他订阅者。
  - 下发指令：`ctx.commands.create_command(command_wire_dict, case_id=None, device_id=None)`。它会做契约校验，检查 depends_on 存在且属于同一账户，并按 command_id 幂等；出错时抛 `CommandCreateError(code)`。
  - 关联事件：`ctx.events.link_case(event_id, case_id)`。
  - 人工处理：写 `ctx.store.insert_manual_action(ManualActionRow(...))`，CommandRecord 会自动带上 `target_kind="command"` 的记录。
  - 心跳中的策略版本：注入 `create_app(policy_version=lambda account_id: ...)`。
  - 新路由：在 `create_app` 里 `include_router`，并在 `test_openapi_consistency.py::IMPLEMENTED` 中加上 operationId。
- **F3（搜索、登录接力）**：`create_app(login_qr_active=lambda device_id: ...)` 控制设备卡片上的 `login_qr_active`。设备认证用 `app.main.DeviceAuth`，控制台认证用 `ConsoleActor`，幂等写操作用 `run_idempotent`，错误用 `ApiError`。`search_candidates` 和 `provide_input` 指令也通过 `create_command` 创建。
- **公共**：
  - 新表在 `db.MIGRATIONS` 末尾追加，不要修改已有条目。
  - 测试复用 `tests/conftest.py` 的 `h` 夹具（Harness：FakeClock、注册设备、造指令、claim/ack/report）和 `assert_shape(data, "<yaml component>")`。按协调者要求，夹具只追加，不改已有行为。
- **D2（指令客户端）**：
  - 领取前必须先发一次心跳，且心跳中的 `account_id` 要与已确认的绑定一致，否则领取一直返回空列表。
  - `claim` 的重试要复用同一个 `claim_key(device_id, attempt_id)`，这样会拿到同一批指令。
  - ack 必须在 `lease_seconds`（默认 60 秒）内完成。
  - 结果回报返回 409 `result_conflict` 时，说明服务端已有不同的结果，不要重试。
- **G（邮件接入）**：用 `serviceToken` 调 `GET /commands?action=forward_resume&status=succeeded&executed_after=...&executed_before=...`，按结果的 `executed_at` 过滤。
- **本地运行**：
  - 启动：`cd monitor/server && uv run python -m app.main serve --db monitor_server.db --port 8000`。默认控制台令牌映射为空，需要在代码中注入 `StaticTokenAuthenticator`；部署配置不在 F1 范围内。

### 失败原因与修改

monitor-v1 上 server 有 57 个失败（server 目录下运行），原因只有两个，服务端业务代码本身不涉及旧字段：

1. **注册被 409 拒绝**：测试注册设备直接用了契约向量 `device_registration_local.json`，向量里的 `contracts_version` 仍是 0.1.0，而服务端已是 0.2.0，兼容性检查按设计返回 409 `contracts_version_unsupported`。凡是先注册设备的用例（ack、cancel、心跳、事件等系列）全部连带失败。修改：`Harness.registration` 改用当前的 `monitor_contracts.__version__`；"不兼容版本"用例的版本号改成 9.9.0。
2. **旧字段 `gui_write_performed`**：只出现在 `tests/conftest.py::Harness.result_body`。改成三个新标志：failed 时三个都为 false；cancelled 时只要求 `outbound_action_performed=false`，沿用向量中 navigation / side_effect 的 true，用来覆盖"导航过、产生过已读回执但没有对外动作时可以取消"这一路径。服务端的结果校验与重复比较都走 `monitor_contracts`，自动跟随 0.2.0，没有改。

### 两种调用方式

| 命令 | 结果 |
| --- | --- |
| `cd monitor/server && uv run pytest` | 106 passed |
| `cd monitor && uv run pytest server` | 106 passed |
| `cd monitor && uv run pytest contracts server` | 297 passed，无警告 |
| `cd monitor && uv run pytest contracts` | 191 passed |
| `cd monitor/server/tests && uv run pytest test_events.py` | 11 passed |

为了不依赖调用方式，做了两处修改：
- 测试模块不再 `from conftest import`。conftest 把自己以唯一的名字登记为 `server_testkit`（`sys.modules`），测试改为 `from server_testkit import ...`。pytest 总是先加载 conftest，所以这样做与 rootdir、import 模式、`pythonpath` 配置都无关，也不会和其他成员将来的 `conftest.py` 重名。
- starlette 对 httpx 的弃用警告改在 conftest 的导入处用 `warnings.catch_warnings` 屏蔽。以前它只在 server 自己的 ini 里过滤，从 `monitor/` 调用时会漏出来。

另：直接在 `monitor/` 下运行裸 `uv run pytest`（全部成员）时，client 有 79 个失败（在 `monitor/client` 目录下运行也一样），属于 D1/D2 的 0.2.0 适配，不在本任务范围；server 在该方式下没有失败。
